Your password goes only to Google. Claude gets a one-time code and trades it for a token.

1 · redirect to Google 2 · log in + Allow 3 · back with a code 4 · code → token 5 · call the API

SPA, mobile app or MCP client? It cannot hide a client_secret, so it adds PKCE: a random one-time proof sent in place of the secret. Every MCP client must use it. How it works: 3.5.

3.5 · PKCE · a stolen code is useless

A phone app cannot hide a secret. PKCE proves that the app that started the login also finishes it.

problem A mobile app, SPA or MCP client runs on your device, so it cannot keep a client_secret. If a bad app catches the redirect code, it can trade the code for your tokens.

0 · no secret 1 · verifier + challenge 2 · log in + Allow 3 · code + verifier → tokens 4 · a stolen code

The verifier never travels until the last step, and by then a stolen code is useless.

3.7 · OIDC · OpenID Connect

OAuth says what an app can do. OIDC adds who you are, on top of the same flow.

problem OAuth gives the app an access_token for an API. It does not say who logged in. Use it as proof of login, and a token made for another app can fool yours.

OIDC adds three things to OAuth
1 · ask for it
scope=openid

Add it, plus email profile, to the same /authorize request. That one word turns OIDC on.

2 · a new token
id_token

A signed JWT about the user: iss, sub, aud, exp, email. It answers “who is this user”, for your app only: aud is your client_id.

3 · standard endpoints
same URLs everywhere

/.well-known/openid-configuration: where everything is.
/userinfo: more profile.
Public keys: to check the id_token signature.

OpenID Provider = Google, Microsoft, Apple, Okta, Auth0 · Relying Party = your app

Same redirect, same code, same /token. You get one more token back.

3.8 · “Login with Google” = OIDC + OAuth

Same Claude, two buttons. An access token says what Claude may do. An id_token says who you are.

connector · OAuth only
“Connect Google Calendar” inside Claude
scope=calendar.readonly → access_token: ya29.a0Af…

Claude may read your calendar. It says nothing about who you are.

sign-in · OIDC on top of OAuth
“Continue with Google” on claude.ai
scope=openid email profile → access_token + id_token

Same code flow. The id_token is a JWT about you, made for Claude. It is what logs you in.

  • don't Log users in with an access_token. A token some other app got for that user would work on yours too.
  • verify Signature with Google's public key, iss is Google, aud is your client_id, exp not passed. A library does all four.
  • store Key the user by sub, not email. A Google email can change; sub never does.

3.9 · MFA · multi-factor authentication

A stolen password is not enough when login also needs a second factor of a different kind

Something you know

password, PIN

Something you have

phone, security key

Something you are

fingerprint, face

Two factors must be two different kinds. Password + security question is still one factor: both are things you know.
